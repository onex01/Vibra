# USB и загрузка (UEFI / BIOS)

Этот документ описывает, как запускать Vibra в QEMU с поддержкой USB (xHCI) и как выбирать между UEFI (OVMF) и BIOS (SeaBIOS).

1) Быстрый запуск (предварительно выполните `./build.sh setup`):

- Обычный запуск (UEFI, без USB):
```
make run
```

- Запуск без графики (headless):
```
make run HEADLESS=1
```

- Запуск с USB-устройствами (xHCI + клавиатура/мышь):
```
make run-usb
```

2) Запуск ISO (UEFI) с USB:
```
make run-iso-usb
```

3) Запуск ISO через SeaBIOS (legacy BIOS) с USB:
```
make run-bios-usb
```

4) Переменные Makefile:
- `ENABLE_USB=1` — добавляет USB флаги в `QEMU_FLAGS` (можно использовать в командной строке, например `make run ENABLE_USB=1`).
- `HEADLESS=1` — запускает QEMU с флагом `-display none`.

5) Установка пакетов на Ubuntu/Debian:
```
make deps-ubuntu
```

6) Примечания по kernel-у:
- В ядре уже есть базовая детекция USB контроллеров (`kernel/src/drivers/usb.rs`). Полная реализация xHCI требует дальнейшей разработки (инициализация очередей, обработка event rings и т.д.).
- Для тестирования USB в QEMU используется `nec-usb-xhci` (совместим с QEMU).

Если хотите, могу:
- Автоматически включать `ENABLE_USB=1` при `make run-usb` (сделано через отдельную цель `run-usb`).
- Добавить примерный тест в `kernel` (например, при инициализации вывод списка USB-контроллеров в serial). Хотите, чтобы я добавил такой тест?

7) Отладка по COM (serial)

- По умолчанию `make run` использует `-serial stdio`, то есть QEMU привязывает сериал к текущему терминалу.
	Это удобно, но если вы используете графический QEMU окно или хотите подключаться извне, доступны альтернативы:

- Serial через TCP (порт 4444 по умолчанию):
	- Запуск: `make run-serial-tcp` (или `make run SERIAL_MODE=tcp SERIAL_PORT=5555`)
	- Подключение: `telnet localhost 4444` или `socat -,raw,echo=0 TCP:localhost:4444`

- Serial в файл: `make run-serial-file` (лог сохраняется в `build/serial.log`).

Проблемы с вводом в shell
- Если QEMU запущен с `-serial stdio` и вы не можете вводить команды в shell, возможно:
	- фокус ввода находится в графическом окне QEMU (переключитесь в терминал с `make run`),
	- или QEMU использует stdin для другого устройства. В таких случаях лучше использовать `run-serial-tcp` и подключаться отдельным клиентом.
