# Матрица тестовых машин

Сводка того, что стоит в машинах, на которых проверяется Vibra. Источник —
`scripts/hw-probe.sh` (Linux), а не прогоны ядра. Статус Vibra — отдельная
колонка и отдельный файл [../verified-hardware.md](../verified-hardware.md).

Обновляется вручную по данным `SUMMARY.md` каждого отчёта.

## Что какая машина проверяет

Разные машины закрывают разные «слепые зоны». Это и есть причина держать
несколько, а не одну.

| Машина | Незаменима для |
|---|---|
| ThinkPad T450 | EHCI-only порты (USB2 на Broadwell), **устройства за внутренним хабом**, MTRR заблокированы прошивкой, нет COM1, NX выключен |
| Atermiter X99 D4 | NVMe, AHCI, два EHCI рядом с xHCI, 512e-диски |
| Мини-ПК i5-8350U | машины без EHCI: путь «только xHCI», `uas`-накопители |
| Lenovo G580 | Ivy Bridge + AHCI, EHCI с хабом; legacy-ветка USB2 на другой платформе |
| Плата FM2 | legacy BIOS (CSM), AMD-чипсет, UHCI/OHCI-компаньоны, IDE-режим |

Ключевой вывод из трёх отчётов: **начиная с Kabylake EHCI в чипсете нет**.
Мини-ПК видит флешки только через xHCI. Поэтому драйвер EHCI нужен именно
для Broadwell/Haswell/Ivy Bridge, и там он почти всегда стоит вместе с
внутренним rate-matching хабом.

## Известные особенности, найденные заранее

Записаны, чтобы не выяснять заново.

| Машина | Особенность | Следствие |
|---|---|---|
| T450 | **флешка на xHCI, а не на EHCI**: `usb 2-1: ... using xhci_hcd` | без рабочего xHCI-перечисления флешка не появится; EHCI на этой машине держит только внутренний хаб `8087:8001`, за которым ничего нет |
| T450 | MTRR заблокированы прошивкой (`LOCK=1`) | `wrmsr` в MTRR даёт `#GP`; WC не включить, скорость решается уменьшением перерисовок |
| T450 | NX выключен в BIOS (`CPUID.80000001H:EDX[20]=0`) | ядро не пишет `EFER.NXE`; W^X деградирует |
| T450 | Порты xHCI читаются пустыми (`PORTSC=0x2a0`) | USB2-линии разъёмов идут в EHCI, а не в xHCI |
| T450 | SATA **в AHCI, линк 6 Гбит/с** под Linux | прежняя гипотеза «режим RAID» неверна; `DET=0` в Vibra — дефект AHCI-драйвера, а не прошивки |
| T450 | COM1 отсутствует | только framebuffer и `/VIBRA.LOG` |
| T450 | EHCI с **64-битной адресацией** — подтверждено ядром (`64bit=yes`) | QH/qTD обязаны быть в расширенной раскладке, иначе `GET_DESCRIPTOR` падает |
| T450 | **в прошивке нет настроек AHCI/RAID** | режим SATA фиксирован; `DET=0` в Vibra — дефект драйвера, а не настройка |
| Мини-ПК | EHCI отсутствует, только xHCI `8086:9D2F` | EHCI-код на таких машинах не выполняется вообще |
| Мини-ПК | накопители через `uas`, не `usb-storage` | в Vibra UAS не поддержан; такие диски должны откатываться на BOT (bInterfaceProtocol 0x50) |
| X99 | диски отдают 512 логических / 4096 физических | 512e, не 4Kn: проверка 4Kn на этой машине не пройдёт |

## Где лежат отчёты

Нормализованные `SUMMARY.md` (без `raw/`) хранятся рядом, чтобы данные не
терялись:

| Машина | Файл |
|---|---|
| ThinkPad T450 | `t450/SUMMARY.md` |
| Atermiter X99 D4 | `x99-d4/SUMMARY.md` |
| Мини-ПК i5-8350U | `mini-pc-i5-8350u/SUMMARY.md` |

Сырые логи остаются вне репозитория: в них серийники, UUID и MAC, а нужные
факты уже сведены в таблицы выше.

## Как пополнить

```sh
./scripts/hw-probe.sh                  # на тестируемой машине
```

Полезно снимать **с подключённой флешкой**: тогда в `lsusb -t` видно, к
какому хосту и через какие хабы она висит.

Затем:

1. Строка в таблицу «Машины» по `SUMMARY.md`.
2. Строка в «Что какая машина проверяет», если машина закрывает новую зону.
3. Строка в «Известные особенности» для всего, что удивило.
4. После реального прогона Vibra — запись в `../verified-hardware.md`.

Правило: в «Машины» попадает только измеренное. Если поле не снимали —
оставьте пустым, а не пишите «вероятно».
