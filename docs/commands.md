# Команды shell

Справка по встроенным командам ядра. Любая команда понимает `--help` / `-h`
и печатает своё краткое описание; `help <cmd>` делает то же самое.

Все команды работают в одном процессе (`kshell`), без fork/exec. Пути
абсолютные или относительные к текущему каталогу (`pwd`).

## Файлы и каталоги

| Команда | Описание |
|---|---|
| `ls [-l] [-a] [path...]` | список файлов; `-l` — права/размер, `-a` — с `.`/`..`, несколько путей |
| `pwd` | текущий каталог |
| `cd <path>` | сменить каталог (`cd` без аргумента — в `/`) |
| `tree [path]` | дерево каталогов; `Ctrl+C` прерывает |
| `cat <file...>` | вывод файла потоково (16 КиБ); бинарные определяются по первой порции |
| `touch <file>` | создать пустой файл |
| `mkdir <dir>` | создать каталог (работает и на смонтированном FAT32) |
| `rmdir <dir>` | удалить **пустой** каталог |
| `rm <path>` | удалить файл или каталог |
| `cp <src> <dst>` | копирование потоком (без загрузки файла целиком) |
| `mv <src> <dst>` | перемещение/переименование (копия + удаление) |
| `edit <file>` | построчный редактор; `Ctrl+Z` — выход без сохранения |

## Диски и файловые системы

| Команда | Описание |
|---|---|
| `disks [-v]` | блочные устройства и разделы: имя, тип, размер, смещение, ФС |
| `mount` | список точек монтирования и устройств |
| `disks [-v]` | диски, разделы, ФС, метки; `-v` — драйвер, модель, сектор |
| `mount <path> auto <dev>` | определить ФС по сигнатуре (read-only) |
| `mount <path> fat32 <dev> [rw]` | FAT32; запись только с явным `rw` |
| `mount <path> ext4 <dev>` | ext2/3/4, только чтение |
| `mount <path> ntfs <dev>` | NTFS, только чтение |
| `mount <path> exfat <dev>` | exFAT, только чтение |
| `mount <path> iso9660 <dev>` | ISO9660 (CD/DVD, `sr0`), только чтение |
| `mount <path> ramfs` | смонтировать RAMFS |
| `mount <path> auto LABEL=<метка>` | найти том по метке (`LABEL=VIBRALOG`) |
| `mount /dev/sdb1 /mnt [rw]` | Linux-подобная форма |
| `umount <path>` / `umount -a` | размонтировать точку (корень `/` защищён) |
| `sync` | сбросить метаданные ФС и boot/shell-журналы |
| `df` | использование ФС и режим монтирования |

Имена устройств: `sda`, `sda1`, `sdb1`… — AHCI, IDE/PATA, NVMe и USB
mass storage нумеруются подряд; CD/DVD — `sr0`, `sr1`.

`ISO9660` (CD/DVD, `sr0`) монтируется только для чтения: PVD, Joliet,
Rock Ridge `NM`, подкаталоги. Multi-extent и UDF не поддержаны.

`exFAT` монтируется только для чтения: boot sector, FAT-цепочки,
contiguous-файлы и каталоги. Запись не реализована.

FAT12/FAT16 не поддерживаются — драйвер работает только с FAT32; `mount`
сообщает об этом явно, а `disks` показывает реальный тип тома.

## Медленный вывод на экран

`diag fb` показывает, из чего складывается прокрутка: memory type
фреймбуфера (переведён ли он в write-combining), стоимость сборки строки,
копирования строки и записи всего экрана, а также сверку часов (`sleep 20 ms`
должен измеряться как 20 мс — иначе числам ниже верить нельзя).

Порядок разбора:

1. `WC NOT applied` — фреймбуфер не удалось перевести в write-combining;
   каждая запись уходит отдельной транзакцией.
2. Большое `build row` при маленьком `write screen` — тормозит сборка
   глифов, а не память (обычно это неоптимизированная сборка).
3. Прокрутка (`scroll: ... cycles/line`) с serial и без: 87 мкс на символ —
   это предел 115200 бод. Если разница велика, берите образ без serial.

## Машина без COM1

Если `[BOOT] COM1: absent — serial output disabled`, serial-лога не будет:
ядро пишет только в framebuffer и в boot-лог на носителе. В QEMU независимый
канал даёт debugcon (`-debugcon file:log.txt -global isa-debugcon.iobase=0xe9`),
куда идут маркеры шагов загрузки; на реальной машине смотрите экран и
`/VIBRA.LOG` на разделе `VIBRALOG` (debug-образ).

## Диагностика

| Команда | Описание |
|---|---|
| `vktst` | интерактивный набор проверок (CPU, память, таймер, ФС, диск, сеть, ядро, лог) |
| `vktst list` / `vktst run <id\|all>` / `vktst report` | неинтерактивные режимы |
| `diag pmm` | PMM: alloc/free/contiguous |
| `diag paging`, `diag paging-test`, `diag vmm` | обход и проверка таблиц страниц |
| `diag wxtest` | `.rodata` отображена read-only |
| `diag heap-test`, `diag heap-check`, `diag heap-big [MiB]` | стресс, целостность free-list, рост кучи |
| `diag timer` | источники времени, RTC, частота IRQ |
| `diag keyboard` | состояние 8042, scan set, очереди PS/2 и USB HID |
| `diag usb` | контроллеры xHCI/UHCI, корневые порты (CCS/PED/speed), устройства, storage |
| `diag disk` | порты AHCI, IDE/NVMe, сигнатуры ФС, DMA-ошибки |
| `diag apic` | LAPIC/IOAPIC и маршрутизация |
| `diag display` | бэкенды, формат пикселя, геометрия |
| `diag fb` | memory type фреймбуфера (PAT/MTRR), staging, замеры сборки строки, записи экрана и прокрутки |
| `diag mtrr`, `diag mtrr wc` | диапазоны MTRR; `wc` помечает фреймбуфер как write-combining |
| `diag hw` | SMBIOS, ACPI-таблицы, FADT |
| `diag power` | путь выключения (PM1_CNT, `_S5`) |
| `diag fault-test`, `diag panic-test` | проверка отчётов (останавливает VM) |
| `kstat` | счётчики прерываний |
| `lspci` | список PCI-устройств |

## Логи

| Команда | Описание |
|---|---|
| `log [N]` | последние N строк boot-лога (по умолчанию 40) |
| `log session [N]` | последние строки журнала shell |
| `log sink` | активные приёмники и объём |
| `log path` | путь файла на носителе |
| `log scan` | какие тома видны и почему не подошли |
| `log attach` | принудительный поиск приёмника |
| `log flush` | сбросить журналы в ramfs и на носитель |

Журналы: `/var/log/boot.log`, `/var/log/shell.log` (ramfs) и
`/VIBRA.LOG`, `/SHELL.LOG` на `VIBRALOG` либо на загрузочном томе.

## Система

| Команда | Описание |
|---|---|
| `version`, `uname -a` | версия и дата сборки |
| `free`, `top [-b]`, `ps`, `kill <pid>` | память, монитор, процессы |
| `date`, `date hw`, `uptime` | время и аптайм |
| `hostname [new]` | имя хоста (`/cfg/hostname`) |
| `whoami`, `id`, `su <user>` | пользователи (демо-модель, без паролей) |
| `neofetch` | сводка о системе |
| `history` | история команд текущей сессии |
| `beep [hz] [ms]` | PC speaker; `beep` без аргументов — короткий сигнал |
| `reboot` | FADT RESET_REG → 0xCF9 → 0x92 → i8042 → triple fault |
| `quit` | ACPI S5 (выключение питания) |

## Сеть

| Команда | Описание |
|---|---|
| `ifconfig` | MAC/IP/шлюз и ARP-таблица |
| `ping <ip> [count]` | ICMP echo через e1000 |

Адрес задаётся статически (`10.0.2.15` для QEMU user-mode); DHCP нет.
`Ctrl+C` прерывает `ping` и другие длинные команды.

## Скрипты

| Команда | Описание |
|---|---|
| `run <file.vs>` | выполнить Vibra Script |
| `run -e <code>` | выполнить код из аргумента |

Движок — legacy-эксперимент, в scope ядра не входит.

## Горячие клавиши

| Клавиши | Действие |
|---|---|
| `Tab` | дополнение команды или последнего слова-пути (циклически) |
| `↑` / `↓` | история |
| `←` / `→` | курсор по строке |
| `Ctrl+A` / `Ctrl+E` | начало / конец строки |
| `Ctrl+K` / `Ctrl+U` | удалить до конца / до начала |
| `Ctrl+L` | очистить экран |
| `Ctrl+C` | отменить строку или длинную команду (`cat`, `tree`, `ping`, `vktst`, `cp`) |
| `Ctrl+Z` | то же, что `Ctrl+C` в редакторе строки |
