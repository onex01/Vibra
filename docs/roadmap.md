# Roadmap — Vibra Kernel

> Текущая версия: **0.2.0-rc.25.5 «Foundation RC25.5»**.
> Цель: стабильное диагностическое ядро на реальном x86_64-железе, не ОС.

Дорожная карта разбита на **серии patch-релизов** внутри каждого minor.
Раньше переходы были крупными («0.3.0: прерывания и блочный слой» — 6 разных
подсистем сразу), из-за чего пункты накапливались и не закрывались. Теперь
один релиз — одна проверяемая тема и один набор тестов.

## Принципы

- Новая версия возможна только после воспроизводимого теста, а не после
  добавления прототипа драйвера.
- До `0.6.0` GUI, приложения и ARM64 не расширяют scope.
- Операции записи на физический диск выключены по умолчанию и требуют
  отдельного тестового носителя.
- QEMU — регрессия; реальная машина — критерий готовности.
- Каждый пункт ниже имеет критерий приёмки и тест (`make ...`). Пункт без
  теста не считается закрытым.
- Нельзя заявлять поддержку железа по QEMU (см. `docs/verified-hardware.md`).

## Легенда

- `[x]` — есть код **и** автоматическая проверка;
- `[~]` — код есть, проверки нет или она только в QEMU;
- `[ ]` — не начато;
- `[!]` — известно, что не работает; описано в «Известных пробелах».

## Что сделано: 0.1–0.2 (база)

Собрано, чтобы не терять контекст; подробности — в `CHANGELOG.md`.

**Boot и платформа.** Limine/UEFI, serial, framebuffer, GDT/TSS/IDT, PIC,
PIT, PS/2, ACPI (RSDP/XSDT/FADT/MADT/MCFG/HPET/SMBIOS), PCI-инвентаризация,
перенос BAR выше 4 ГиБ в низкое MMIO-окно.

**Память.** PMM (битмап, next-fit, contiguous), heap с ростом по требованию
(8 МиБ → 64 МиБ), free-list с коалесценцией и самодиагностикой, копия PML4
Limine, read-only page-table walker, `diag paging/paging-test/vmm/wxtest`.

**Время.** TSC (invariant, калибровка по HPET/PIT ch2) → HPET → PIT IRQ;
CMOS RTC; `date`, `date hw`, `uptime`, `diag timer`, LAPIC-timer fallback.

**Хранилище.** AHCI (ATA read/write, ATAPI CD), IDE/PATA (read-only, теперь
в block layer), NVMe (Identify, I/O queues, 512/4096 байт/блок),
USB mass storage (xHCI/EHCI BOT/SCSI), GPT/MBR/EBR, 4Kn, `sdX`/`srX`,
FAT32 (rw), ext2/3/4 (ro, extents/64bit/htree), NTFS (ro, MFT/index),
`mount auto`, `umount`, `sync`, `VIBRALOG`.

**Ввод.** PS/2 (Set 1/2, polling fallback), USB HID boot keyboard на xHCI,
UHCI-клавиатуры, PS/2 мышь (базово).

**Сеть.** e1000 (RX/TX, ARP, IPv4, ICMP), RTL8139 (инициализация),
`ping`, `ifconfig`; DHCP/TCP/UDP нет.

**Диагностика и UX.** `vktst`, `diag` (21 подкоманда), `top`, `free`, `tree`,
`ls -l/-a`, `mount/umount/sync`, история, Tab, `Ctrl+C/Ctrl+Z`,
boot/shell-логи в ramfs и на носителе, ACPI S5/reset.

**Надёжность.** Паника и page fault без аллокаций, полный IDT (0..32),
DMA-адрес из таблиц страниц, read-only по умолчанию, проверка битых ФС.

## 0.2.x «Foundation hardening» — довести базу до честного 0.2.0

Цель серии: закрыть дефекты, которые ломают работу на реальном железе, и
сделать 0.2.0 финальным. Каждый patch-релиз — одна тема.

### 0.2.0-rc.10 — большие тома и NTFS

- [x] `DiskIo::dma_address` из таблиц страниц; AHCI/NVMe/RTL8139 не
  программируют PRD/PRP при неудачной трансляции.
- [x] VIBRALOG ищется первым на всех дисках; загрузочный том — только
  fallback после shell.
- [x] IDE/PATA в `blockdev::probe`; `sector_size()` = 512.
- [x] MBR на 4Kn: LBA таблицы разделов переводятся в 512-байтные единицы.
- [x] NTFS читается потоково (файл любого размера, без лимита 64 МиБ).
- [x] `disks` показывает `gpt`/`mbr` вместо `unknown`.
- [x] `make big-fs-test`: NTFS 2 ТБ целиком, GPT-раздел за 2 ТБ,
  MBR на 4Kn-устройстве.

### 0.2.0-rc.11 — диски, FAT-семейства и целостность ФС

- [x] `DiskEntry`: драйвер/модель/серийник/размер сектора, `disks -v`.
- [x] `detect_fs_type` различает FAT12/16/32 по BPB; маленькие FAT32-тома
  не путаются с FAT16.
- [ ] FAT32: создание LFN-имён (сейчас только 8.3), корректный FSInfo,
  обновление `free_clusters`.
- [ ] FAT32: порядок записи «данные → размер → FAT» зафиксировать
  тестом `power-loss` (обрыв QEMU через `quit`/SIGKILL на разных этапах).
- [ ] `fsck`-lite: проверка цепочки кластеров, потерянных кластеров и
  cross-link при монтировании (read-only отчёт, без исправлений).
- [ ] `sync`/`umount` для FAT32: дождаться завершения всех записей, запрет
  `umount` при открытых файлах.
- [ ] Тест: 100 циклов `mount → cp → sync → umount → проверка на хосте`.

**Выход:** запись на FAT32 не портит том при обрыве на любом шаге; повторный
`cp` не создаёт дубликаты и «потерянные» кластеры.

### 0.2.0-rc.12 — монтирование по метке и надёжность ввода

- [x] `mount <path> auto LABEL=<метка>`: метка FAT читается из BPB, имя
  GPT-раздела — из таблицы; `disks` показывает колонку LABEL.
- [x] `disks -v`: драйвер, модель, серийник, размер логического сектора.
- [x] Клавиатура: break-код левого Shift (`0xAA`) отбрасывался как «i8042
  self-test OK», из-за чего модификатор залипал навсегда — после первой
  заглавной буквы `help` набирался как HELP. Фильтр применяется только к
  scan code set 2.
- [x] `make keyboard-test` проверяет смешанный регистр (`echo MiXeD`).
- [x] `make big-fs-test` монтирует том по `LABEL=LABELVOL`.
- [ ] `mount` по UUID раздела (GPT GUID, FAT `VolumeSerialNumber`).
- [ ] Неоднозначность меток: если метка встречается дважды, требовать
  явное имя устройства, а не монтировать первый попавшийся том.

**Выход:** том можно смонтировать, не зная его `sdX`; заглавные буквы
работают на PS/2 и USB HID.

### 0.2.0-rc.13 — exFAT read-only

- [x] exFAT read-only: boot sector, FAT-цепочки, `NoFatChain`
  (contiguous-файлы), каталоги (0x85/0xC0/0xC1), имена UTF-16, метка тома
  (0x83) для `disks` и `mount LABEL=`. Закрывает типичный внешний HDD.
- [ ] exFAT: сверка name hash по upcase-таблице (сейчас имена сравниваются
  без неё) и allocation bitmap для `fsck`-подобной проверки.
- [ ] ISO9660 read-only для `sr0` (PVD, directory records, Rock Ridge/Joliet
  как минимум по именам).
- [x] `detect_fs_type`: FAT12/16 классифицируются по BPB (число кластеров),
  а не по строке `FAT32`; `disks` показывает `fat16`, `mount` объясняет,
  что поддержан только FAT32.
- [ ] FAT12/16 read-only драйвер (сейчас — только корректная диагностика).
- [x] Тест exFAT: `make big-fs-test` — фикстура
  `scripts/mk-exfat-fixture.py` (contiguous-файл, подкаталог, файл из двух
  кластеров через FAT) плюс монтирование по метке.

**Выход:** внешний HDD в exFAT монтируется read-only и читается, включая
файлы больше кластера; ISO9660 остаётся на следующий patch.

### 0.2.0-rc.14 — ISO9660 (CD/DVD)

- [x] Primary Volume Descriptor в LBA 16, геометрия блока из PVD (2048 байт).
- [x] Joliet (UCS-2 BE, escape `%/@`, `%/C`, `%/E`) и Rock Ridge `NM`:
  длинные имена и нижний регистр читаются как есть.
- [x] Каталоги, подкаталоги, extent'ы; файл читается по требованию.
- [x] `mount auto sr0` и `mount <path> iso9660 <dev>` → `OK (iso9660, ro)`.
- [x] Метка тома (Volume Identifier) в `disks` и `mount LABEL=`.
- [x] `make iso-test`: образ genisoimage на CD-ROM через ATAPI, листинг,
  чтение файлов корня и подкаталога, размер extent'а 100 КиБ.
- [ ] Multi-extent (флаг 0x80) и continuation area (CE) — записи
  пропускаются; для больших файлов на некоторых образах это заметно.
- [ ] El Torito / hybrid MBR: загрузка с самого ISO, а не только чтение.
- [ ] UDF (DVD-Video, большие образы) — сейчас не поддерживается.

**Выход:** диск, на котором лежит ядро, читается как ФС; `sr0` не просто
блочное устройство.

### 0.2.0-rc.15 — загрузка без COM1

Первый запуск на ноутбуке встал на `[BOOT] Step 4: Heap stress`. Причина не в
куче: `serial::poll_key()` опрашивал порт 0x3F8, не проверяя, есть ли UART.
Без COM1 порт читается как 0xFF, `LSR.DR` всегда 1, и `poll_key()` крутился
вечно. В QEMU это воспроизводится `-serial none`, то есть все прежние тесты
(`-serial file:`) этот путь просто не покрывали.

- [x] `try_read_byte`: без `SERIAL_PRESENT` порт не опрашивается; `LSR == 0xFF`
  выключает опрос до конца работы.
- [x] `poll_key`: бюджет байт на вызов — поток мусора возвращает управление,
  а не вешает ядро.
- [x] `handle_interrupt`: ограниченный цикл вместо `while` (в прерывании
  зависание было бы ещё хуже).
- [x] Маркеры хода загрузки на debugcon (порт 0xE9) — единственный канал на
  машинах без COM1.
- [x] `make noserial-test`: загрузка с `-serial none` до shell по debugcon-маркерам.
- [x] `make serial-input-test`: ввод именно через COM1 (раньше все shell-тесты
  подавали клавиши через monitor, и serial-путь не проверялся).
- [ ] Поведение при ACPI-описанном 16550, но без физического разъёма
  (проверить на железе: `dmesg`-эквивалент должен показать `COM1: absent`).
- [ ] То же для PS/2: `drain_controller` защищён от `0xFF`, но нужен тест
  «клавиатуры нет» (сейчас проверяется только наличие).

**Выход:** ядро грузится до shell на машинах без COM-порта и без PS/2,
а отсутствие устройства не выглядит как зависание.

### 0.2.0-rc.16 — скорость консоли

Жалоба с ноутбука: «пока экран пустой — моментально, как дошло до низа —
тормозит». Разбор по замерам, а не по догадкам: `diag fb` меряет каждый этап
отдельно, включая проверку самих часов.

- [x] Профили Cargo перенесены в корневой `Cargo.toml` (в члене workspace они
  игнорировались): debug-сборка шла с `opt-level = 0`, из-за чего сборка
  строки стоила 2 млн циклов вместо 12 тысяч.
- [x] Отрисовка строки: сборка глифов в RAM-буфер и одна широкая копия на
  пиксельную строку вместо 64 записей на символ.
- [x] Прокрутка перерисовывает только область до последней непустой строки.
- [x] Фреймбуфер переводится в write-combining через PAT (`IA32_PAT[4]`).
- [x] `diag fb` — замеры по этапам (сборка, копия, экран, прокрутка) плюс
  сверка часов.
- [x] Варианты debug-образа: с serial и без (`iso-debug-noserial`,
  `usb-debug-noserial`).
- [ ] Serial-зеркало: сейчас каждый символ ждёт THRE (87 мкс при 115200).
  Нужен буфер TX с выгрузкой из айдла, чтобы debug-сборка не платила за
  serial, но лог не терял байты.
- [ ] Проверить на реальном железе: `diag fb` должен показать `WC` и
  прокрутку без «ступеньки» на заполнении экрана.
- [ ] Кэш глифов: сейчас каждый символ разворачивается в пиксели заново;
  для повторяющихся строк (`ls -l`, таблицы) это заметная доля.

**Выход:** вывод в shell не замедляется при заполнении экрана ни в release,
ни в debug-сборке.

### 0.2.0-rc.18 — USB3, hotplug и таймауты по времени

- [x] EP0 для SuperSpeed — 512 байт (было 64), `bMaxPacketSize0` больше не
  отфильтровывается диапазоном `8..=64`.
- [x] SuperSpeed Endpoint Companion: `bMaxBurst` разбирается и попадает в
  endpoint context; `max_transfer` считается по burst.
- [x] Hotplug: событие PORT_STATUS_CHANGE выставляет флаг, `poll_hotplug`
  перечисляет новые устройства и убирает отключённые; block layer
  пересобирает записи USB-дисков.
- [x] `storage::refresh()` — список накопителей синхронизируется.
- [x] `diag usb` показывает корневые порты и сырой `PORTSC`.
- [x] `make usb3-test`: QEMU `qemu-xhci` + `port=1` (SuperSpeed),
  монтирование и hotplug через `device_del`/`device_add`.
- [x] **Таймауты по времени вместо итераций** в NVMe: после перехода на
  `opt-level = 1` фиксированные 5 000 000 итераций стали ≈15 мс вместо 150.
- [x] Подтверждено на T450: ни один из 15 портов xHCI не видит подключения
  (`PORTSC=0x2a0`), потому что USB2-половину разъёмов обслуживает EHCI
  (`8086:9CA6`), драйвера которого нет.
- [ ] Хабы (класс 09) — нужны, только если порты идут через внешний хаб.
- [ ] Отключение слота (Disable Slot) и сброс контроллера при зависании.

**Выход:** на машине с портами, отданными xHCI, флешка появляется в `disks`,
монтируется, VIBRALOG пишется, переподключение не требует перезагрузки.
На T450 порты у EHCI — это закрывает rc.25.

- [x] AHCI: `COMRESET` перед повтором `identify_device`; ожидание BSY/DRQ и

- [x] `detect_fs_type` печатает ошибку чтения сектора 0, а не молчит.

**Выход:** `diag fb` показывает настоящий memory type, а не догадку.

### 0.2.0-rc.25 — EHCI (USB 2.0)

Причина: на Haswell/Broadwell USB2-половина каждого USB3-разъёма висит на

- [x] PCI: `class 0x0C`/`subclass 0x03`/`prog_if 0x20`, memory BAR0,

- [x] Legacy handoff через `USBLEGSUP` (EECP): OS owned, SMI off.
- [x] Init: `HCRESET`, `CONFIGFLAG.CFL = 1`, `USBCMD` Run+ASE, ожидание

- [x] Порты: сброс (`PR` → `PE`/`PEC`), `PP`, скорость (`PS`; на QEMU —

- [x] Async schedule: QH (48 Б, выравнивание 32) и qTD (32 Б), адреса через

- [x] Control transfers: `GET_DESCRIPTOR`, `SET_ADDRESS`,
  `SET_CONFIGURATION`, `GET_MAX_LUN`, BOT reset.
- [x] Bulk IN/OUT через qTD, software data toggle (BOT: CBW = DATA0,
  data/CSW = DATA1).
- [x] `enum UsbHost { Xhci, Ehci }` и диспетчеризация: BOT/SCSI

- [x] Hotplug EHCI: `PORTSC.CSC`, перечисление и удаление, общий

### 0.2.0-rc.25.3 — DMA-буфер без барьера и дамп маршрутизации

Две настоящие причины, обе найдены по логам T450.

**AHCI: `IDENTIFY returned 0 sectors` при живом диске.** После правки
`GHC.AE` линк поднялся (`DET=3`), команда завершалась без ошибок
(`TFD=0x50` — DRDY), но слова 100..103 IDENTIFY были нулями.

- Буфер заполняет DMA, а читался обычной загрузкой. Компилятор вправе
  поднять её выше ожидания завершения команды, и тогда парсится то, что
  лежало в памяти до передачи. Добавлен `compiler_fence(SeqCst)` перед
  разбором; побайтовый `read_volatile` не годится — он замедлял каждый
  сектор и растягивал загрузку.
- Заодно закрыт use-after-free: срез `data` читался уже после `dealloc`,
  поэтому диагностика печатала мусор из освобождённой кучи.
- В диагностику добавлен `PRDBC` — сколько байт реально перенёс DMA.
  Ноль при DRDY означает проблему PRD, а не «диск без секторов».

**USB: порты не видит ни один контроллер.**

- xHCI: все 15 портов `0x2a0` = `PP=1`, `PLS=5(RxDetect)`, `CCS=0`,
  при `PPC=0` (питанием управляет прошивка, писать нечего).
- EHCI: порт 1 занят внутренним хабом `8087:8001`, порты 2 и 3 пусты.
- Linux видит на xHCI флешку, камеру и Bluetooth. Значит порты
  **маршрутизированы** не туда: у Intel EHCI в PCI-конфигурации есть
  регистры маршрутизации USB2-портов, и Linux выставляет их сам.
- [x] `diag usb` печатает `[usb2 port routing]` — PCI-конфигурацию
  контроллеров по смещениям `0x80..0x8C`. По ней видно, куда реально
  отправлены порты.
- [ ] Выставить маршрутизацию так, как это делает Linux, и проверить
  `CCS` на портах xHCI.

### 0.2.0-rc.25.4 — Intel-маршрутизация портов: их надо отдать xHCI

Настоящая причина, почему xHCI не видел ни одного устройства.
`diag usb` в rc.25.3 показал регистры маршрутизации, и сравнение с PCI-
конфигурацией под Linux дало точный ответ.

Linux, xHCI `00:14.0`:

```text
d0: ff 07 00 00  ff 04 00 00  0f 00 00 00  0f 00 00 00
```

Это регистры Intel в PCI-конфигурации xHCI:

| Смещение | Регистр | Значение Linux | Смысл |
|---|---|---|---|
| `0xD0` | `XUSB2PR` | `0x000007ff` | 11 линий USB2 отданы xHCI |
| `0xD4` | `USB2PRM` | `0x000004ff` | маска переключаемых линий |
| `0xD8` | `USB3_PSSEN` | `0x0000000f` | 4 линии SuperSpeed включены |
| `0xDC` | `USB3PRM` | `0x0000000f` | маска переключаемых линий |

У Vibra `0xD0` и `0xD8` не трогались, то есть оставались нулями: все
USB2-порты принадлежали EHCI, а SuperSpeed был выключен. Отсюда «15
портов, 0 connected» при `PP=1` и `PLS=5 (RxDetect)`, и одновременно живой
внутренний хаб на EHCI. Linux делает это в `usb_enable_intel_xhci_ports()`
и потому видит флешку, камеру и Bluetooth на xHCI.

- [x] `enable_intel_port_routing()`: при непустых масках `USB2PRM`/
  `USB3PRM` записываются `USB2PR = 0xFFFF` и `USB3_PSSEN = 0xF` до
  инициализации контроллера, с логом «было -> стало».
- [x] Регистры не трогаются, если обе маски нулевые (не Intel или порты
  не переключаются): у чужих контроллеров `0xD0..0xDC` заняты под другое.
- [x] `diag usb` печатает также `0xD0`, `0xD4`, `0xD8`, `0xDC`.
- [x] Ожидание `COMRESET` на пустом порту сокращено (40 000 прокруток
  вместо 500 000): пять пустых портов заметно удлиняли загрузку.

**Подтверждено на T450:** флешка появилась в `disks` (`sda`, 3648 MB,
`iso9660`, разделы `sda2` fat12 / `sda5`/`sda7` fat32), монтируется и
читается, `rm` на смонтированном FAT32 работает. Значит маршрутизация
была настоящей причиной.

### 0.2.0-rc.25.5 — приглашение после hotplug, запись лога не блокирует ввод

Три дефекта из прогона rc.25.4 на T450.

**Приглашение пропадало после сообщения о USB.** Сообщение
`[USB] port change: ...` печаталось посреди ввода, а строка ввода после
него не восстанавливалась: shell выглядел повешенным, хотя продолжал
читать клавиатуру.

- [x] `reprint_input()` рисует приглашение заново и восстанавливает начало
  строки ввода по тем же формулам, что и при входе в `read_line`, поэтому
  набранный текст и позиция курсора остаются на месте.

**Инпутлаг при воткнутой флешке.** `boot_log::checkpoint()` вызывался раз
в секунду прямо в цикле ввода. Когда лог пишется на тот же USB-накопитель,
запись занимает сотни миллисекунд, и клавиатура ждёт её в этом же цикле.

- [x] Запись лога перенесена в ветку простоя: пока есть нажатия, она не
  выполняется вообще.
- [x] Длительность замера: если `checkpoint` занял больше 100 мс, интервал
  удваивается (до 15 с), в лог один раз пишется
  `[LOG] checkpoint took N ms: flash writes are slow, backing off`.
  Быстрые записи возвращают интервал к 1 с.

**Накопитель «отваливался» в I/O error.** После одного неудачного bulk
transfer endpoint остаётся в состоянии Halted, и контроллер отвечает
ошибкой на все последующие команды — до переподключения устройства.
Отсюда картина «смонтировал, прочитал, потом I/O error, после повторного
монтирования снова работает».

- [x] `recover_endpoint()`: `Reset Endpoint` + `Set TR Dequeue Pointer`
  (Endpoint ID в bits 20:16, DCS от текущего cycle) и одна повторная
  передача.
- [x] Код завершения печатается в лог: без него `I/O error` не с чем
  сопоставить.

**Выход:** ввод не замирает при воткнутой флешке, приглашение всегда на
месте, запись на накопитель переживает единичный сбой.

## 0.4.x «Storage write path»

Read-only база есть; серия добавляет безопасную запись и целостность.

### 0.4.1 — единый DMA-контракт

- [ ] `DmaBuffer`/`DmaDirection`/ownership для всех драйверов; запрет
  `Layout::from_size_align(...).unwrap()` на пути драйвера.
- [ ] Bounce-буфер для буферов, не пригодных для DMA (стек, `.bss`).
- [ ] PRP-list для NVMe (сейчас только PRP1) и несколько PRD для AHCI.
- [ ] Cache-coherency: явный контракт (x86 — coherent, но задокументировать
  и проверить на ARM64 позже).
- [ ] `diag dma` — карта выданных буферов, отказы трансляции.
- [ ] Тест: NVMe/AHCI I/O по 1 МиБ в 4 КиБ буфер и обратно.

### 0.4.2 — запись: FAT32 и общая модель

- [ ] Явный write-path в VFS: `open(O_RDWR)`, `flush`, `fsync`, `truncate`.
- [ ] FAT32: LFN-создание, переименование, `mkdir/rmdir`, `free_clusters`,
  зеркалирование FAT.
- [ ] Порядок записи и crash-consistency: журнал намерений в свободных
  кластерах (мини-FAT-journal) либо чётко задокументированный «last write
  wins».
- [ ] `mount rw` требует отдельного подтверждения на устройстве без метки
  тестового носителя (сейчас просто `rw`).
- [ ] Тест: `make write-test` — 100 циклов записи и `fsck.fat` после
  каждого; обрыв питания на каждом этапе.

### 0.4.3 — ext2/3/4 и NTFS

- [ ] Решение по ext4 write: либо реализовать (bitmap, journal replay,
  extents), либо официально зафиксировать read-only навсегда.
- [ ] NTFS: `$Bitmap`/`$UpCase` не нужны для чтения, но нужен корректный
  `$DATA` с несколькими runs и sparse — проверить на больших файлах.
- [ ] `stat`: реальные даты создания/изменения из MFT и inode.
- [ ] Тест: файлы > 4 ГиБ на NTFS/ext4 (чтение потоково).

### 0.4.4 — съёмные носители

- [ ] Автомонтирование при подключении (по метке/ФС) с уведомлением, а не
  только `mount`.
- [ ] Защита: запрет записи, пока том не размонтирован другим потребителем.
- [ ] `eject`/`umount -l` для USB.
- [ ] Тест: подключить/отключить USB 10 раз, проверить отсутствие
  «залипших» записей и паники.

## Известные пробелы (`[!]`)

Список того, чего сейчас **нет**, чтобы не было иллюзий и резких переходов.

- [!] Нет записи на ext2/3/4 и NTFS (только FAT32).
- [!] Нет «горячего» определения не-USB устройств: если UART/PS2 исчезнет
  после probe, опрос прекращается (UART) или обрывается (PS2). USB hotplug
  есть для xHCI и EHCI (с rc.25.1 — без блокировки ввода).
- [!] ISO9660 без multi-extent/CE: файлы, разбитые на несколько extents,
  пропускаются (образы с >4 ГиБ файлами). UDF не поддерживается.
- [!] exFAT только для чтения: name hash не сверяется, bitmap не читается.
- [!] Один NVMe-контроллер; несколько namespace не поддержаны.
- [!] EHCI проверен только в QEMU. На T450 устройства висят за внутренним
  хабом, поэтому нужен класс 09 (rc.25.6) — запись в
  `docs/verified-hardware.md` ждёт железа.
- [!] AHCI на T450 читает `DET=0`, хотя Linux видит линк 6 Гбит/с в режиме
  AHCI: дефект драйвера, а не прошивки.
- [!] USB: нет хабов (класс 09) — без них не работают внешние USB2-порты
  на Broadwell/Haswell/Ivy Bridge (rc.25.6).
- [!] USB: нет OHCI (USB 1.1, NEC/AMD/VIA).
- [!] USB HID на EHCI не поддержан (только mass storage; клавиатуры —
  через xHCI/UHCI/PS2).
- [!] Нет MSI/MSI-X; все драйверы на polling.
- [!] Нет IOAPIC-маршрутизации; PIC остаётся основным.
- [!] Нет SMP, per-CPU данных и TLB shootdown.
- [!] Нет userland ABI: per-process CR3, ELF, fork/exec, сигналов.
- [!] FPU/SIMD-контекст не сохраняется между задачами.
- [!] Нет DHCP/UDP/TCP/DNS; сеть — статический адрес QEMU.
- [!] Нет backtrace с символами в panic.
- [!] Нет `umount`-защиты от открытых файлов (файлы не отслеживаются).
- [!] Нет проверки целостности ФС при монтировании.
- [!] W^X не enforced для `.text/.rodata` собственных таблиц (наследие Limine).
- [x] `docs/verified-hardware.md` заполнен для T450: framebuffer, PS/2,
  MTRR locked, NX off, EHCI, SATA `DET=0`, отсутствие COM1.
- [!] Одна машина в матрице; нужны ещё минимум две разных платформы.
- [!] COM1 отсутствует на T450, поэтому serial-путь проверен только в QEMU.

## Порядок работ

1. **0.2.x**: EHCI (rc.25) → разделение serial (rc.26–27) → несколько
   дисков (rc.28) → память (rc.29) → наблюдаемость (rc.30) → финальный 0.2.0.
2. **0.3.x**: APIC → MSI → IRQ-драйверы → таймеры.
3. **0.4.x**: DMA-контракт → запись → съёмные носители.
4. **0.5.x**: OHCI и хабы → ввод → периферия.
5. **0.6.x**: NIC → IPv4/DHCP → TCP.
6. **0.7.x**: userland.
7. **0.8.x**: SMP.
8. **0.9**: ARM64.

Правило: нельзя начинать следующую серию, пока предыдущая не имеет зелёных
тестов и записи в `docs/verified-hardware.md` (или явного решения отложить
hardware-проверку с пометкой в `docs/roadmap.md`, раздел «Известные пробелы»).
