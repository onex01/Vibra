# Питание, файловая система и логи

Три подсистемы, у которых общая история: каждая работала «в QEMU», но на
реальном железе вела себя иначе. Здесь зафиксировано, что именно было
исправлено и как это проверить.

## Выключение питания (`quit`)

`quit` пишет `SLP_TYP | SLP_EN` в блок `PM1a_CNT` (и `PM1b_CNT`, если он есть)
по адресам из FADT. Значение `SLP_TYP` берётся из AML-пакета `_S5` в DSDT —
это не константа, и на части платформ жёстко зашитая пятёрка просто не
выключает машину.

Разбор `_S5` намеренно минимальный: полноценный AML-интерпретатор не нужен,
пакет состоит из констант. Поддерживаются все встречающиеся варианты
элементов:

| AML-кодировка | Смысл | Пример |
|---|---|---|
| `0x00` | `Zero` | QEMU: `Name (_S5, Package (4) { 0, 0, 0, 0 })` |
| `0x01` | `One` | |
| `0x0A xx` | `BytePrefix` + значение | большинство прошивок: `0x0A 0x05` |
| `0x0B lo hi` | `WordPrefix` | редко |

Раньше команда писала `0x2000` в порт `0x604` (это `PM1a_CNT` **только у
QEMU q35**) и `0x03` в порт `0x92` (это ACPI **reset**, а не poweroff).
На реальном железе `quit` поэтому либо ничего не делал, либо перезагружал
машину.

Порядок попыток в `acpi::power::power_off`:

1. `PM1a_CNT`/`PM1b_CNT` с `SLP_TYP` из `_S5` (при необходимости сначала
   поднимается `SCI_EN` через `SMI_CMD`);
2. те же порты с `SLP_TYP = 5` — если `_S5` не разобрался;
3. известные порты эмуляторов: `0x604` (q35), `0xB004` (i440fx),
   `0x4004` (VirtualBox);
4. ACPI reset (`0x92` бит 0) — лучше перезагрузка, чем вечное `hlt`.

Диагностика: `diag power` печатает `PM1a_CNT`, `PM1b_CNT`, найденный
`SLP_TYP` и адрес DSDT. Если `quit` не выключает машину, этот вывод
показывает, на каком шаге всё остановилось.

`reboot` переведён на тот же ACPI reset (`0x92`), а `0x64/0xFE` оставлен
резервным: на части платформ i8042 уже переведён в другой режим и команду
игнорирует.

## Каталоги на FAT32

`Fat32Fs::mkdir` и `Fat32Fs::rmdir` раньше возвращали `NotSupported`, хотя
запись файлов (`write_range`, `alloc_cluster`, `free_chain`) уже была
реализована. Теперь:

- `mkdir` выделяет кластер, обнуляет его, пишет записи `.` (на себя) и `..`
  (на родителя) и добавляет 8.3-запись с атрибутом `ATTR_DIRECTORY`;
- для каталога в корне `..` содержит кластер 0, а не номер корневого
  кластера — иначе том не проходит проверку консистентности;
- `rmdir` удаляет только пустой каталог (`NotEmpty` иначе) и не даёт удалить
  корень; записи `.`/`..` пустотой не считаются.

Отдельная проблема была в маршрутизации: `fs::create_dir` работал **только**
с `LEGACY_RAMFS`, поэтому `mkdir /mnt/x` на смонтированном FAT32 не создавал
ничего. Добавлены `vfs_mkdir`/`vfs_rmdir`/`vfs_remove`, и `create_dir`,
`remove_entry`, `remove_dir` идут сначала в VFS, а в RamFS — только если путь
не принадлежит ни одной точке монтирования.

Появилась команда `rmdir` (только каталоги, в отличие от `rm`).

Ext2 остаётся read-only: запись требует bitmap блоков и inode, работы с
группами и журналом — это отдельная задача, а не побочная правка.
Полурабочая запись здесь опаснее отказа: она портит чужие тома.

FAT32 теперь тоже **read-only по умолчанию**: `mount <path> fat32 <dev>` и
`mount <path> auto <dev>` монтируют том только для чтения. Запись включается
явно — `mount <path> fat32 <dev> rw`; `mount_point_of`/VFS проверяют флаг
`readonly` и возвращают `ReadOnly` даже для ФС, которые сами его не проверяют.
Это соответствует принципу roadmap: операции записи на физический носитель не
должны включаться случайно.

## Запись логов

`boot_log` держит кольцо на 128 КиБ и умеет три приёмника:

| Приёмник | Когда доступен |
|---|---|
| `/var/log/boot.log` (ramfs) | всегда после `init_filesystem` |
| `/VIBRA.LOG` на FAT32-томе с меткой `VIBRALOG` | когда найден такой том |
| QEMU debugcon (порт `0xE9`) | `[TICK]`, `[HALT]`, `[HEARTBEAT]` |

Дисковый приёмник раньше собирался только с `--features boot-log-to-usb`, и в
обычной сборке лог жил лишь в ramfs — то есть исчезал при выключении. Теперь
модуль компилируется всегда, а `attach()` вызывается на boot и из idle.

Найденный при этом дефект: `attach()` троттлился только после исчерпания
boot-попыток (`attempts >= MAX_BOOT_ATTEMPTS`). Если за время boot диски не
появились и счётчик остался нулевым, то после загрузки `attach()` сканировал
носители на **каждом** `checkpoint()` — раз в секунду и на каждое нажатие
клавиши. Теперь троттлинг действует всегда (`IDLE_RETRY_MS = 5000`).

Команды:

- `log` — последние 40 строк;
- `log <N>` — последние N строк;
- `log sink` — какие приёмники активны и сколько байт записано;
- `log flush` — принудительный `checkpoint()` с отчётом;
- `log path` — путь файла на носителе.

`quit` и `reboot` перед выключением сохраняют лог в ramfs и вызывают
`checkpoint()`, чтобы последние строки не потерялись.
